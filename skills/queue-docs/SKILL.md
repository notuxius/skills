# Document ticket workflows

Identify the reader's task and permission level. Check the current interface, product language, and behavior through the UI or tests before writing steps. Use the exact visible control and status labels.

- State the prerequisite that lets the reader start the task, such as access to the relevant queue. Keep each step to one action and give the reader the visible result that confirms completion.
- For a ticket claim, verify when the interface reports success and where the agent can confirm the owner. If someone else claims it first, document the visible message and the next action the interface supports.
- When a status or filter matters, explain how it affects the tickets the reader can see. Verify any retry, refresh, or alternate path before including it.
- Use a sample ticket for walkthroughs and screenshots. Check the final sequence against the supported interface and tie troubleshooting to messages the reader can actually see.
